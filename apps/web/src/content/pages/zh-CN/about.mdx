## 我是谁

我是 Yuri Cunha，一个对计算机、服务器、系统和 homelab 有点过于认真的巴西人。这个网站放着我的项目、笔记、实验，以及那些先把东西弄坏后才学到的经验。

## 一句话介绍

我是一名 **Infrastructure & Platform Engineer**，喜欢构建和运行完整的系统：从硬件、Linux 和网络，到存储、容器、服务、数据库、自动化，以及运行在其上的应用程序。数据库是我工作中重要的一部分；扎实的软件开发背景让我能够追踪跨越应用和底层平台边界的问题。

## 系统与基础设施

我喜欢靠近真正会动的部分。我想知道进程在哪里运行、如何启动、数据放在哪里、机器怎样通信，以及服务行为异常时怎样恢复系统。

我的工作和实验涉及 Linux 服务器、Docker 和 Compose、持久化存储、私有网络、云端与本地工作负载、自托管服务、脚本、CI、日志、监控和故障排查。最能描述它的链路很简单：hardware → Linux → network → storage → containers → services → databases → automation → applications。

## homelab 与硬件

homelab 不只是学习一种数据库的地方。它是一个真实、持续变化的环境：我在物理机器与云节点、x86 与 ARM64、私有网络与公开入口之间构建、运行、弄坏、恢复并记录系统。

服务器和 homelab 硬件是我最喜欢的部分之一：评估 CPU、内存、ECC、存储、功耗和容量；理解每台机器适合做什么；并为每个工作负载安排合理的位置。我和关心上面运行的服务一样关心机器本身及其限制。

## 开发与数据库

开发仍然是我工作中实用的一部分。我使用 Python、shell、Go、Node.js、TypeScript、SQL 和 Web 工具来编写脚本、自动化、API、内部服务和集成。这个背景在故障跨越多个层次、答案不只是“重启容器”时尤其有用。

PostgreSQL、pgvector、Redis、备份与恢复、数据迁移、性能排查和持久化服务都是我经验的重要部分。数据库是我深入处理的一层，不是我全部的标签。

## 我的工作方式

我偏好可理解、可观测、可恢复的系统。这通常意味着贴近工作的文档、有用的日志和指标、经过验证的备份、用于重复任务的小型自动化，以及不依赖口口相传就能复现的环境。

我喜欢简单到凌晨三点也能修好的工具。对我来说，理解工具背后的机制比记住一长串命令更重要。

## 方向

我的学习经历包括在 Estácio 学习 Database Technology，这仍然影响着我对数据和有状态系统的思考。职业方向很明确：基础设施与平台，将 systems engineering、Linux、networking、containers、automation、cloud、self-hosting 和 databases 视为彼此连接的整体，而不是不同职位的盒子。

## 技术之外

我也在意多运动、跑得更远，并建立能长期坚持的习惯。处理顽固服务时需要的耐心，在终端之外同样有用。

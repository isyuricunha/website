## 自己紹介

私は Yuri Cunha です。コンピューター、サーバー、システム、そして homelab を少し真剣に考えすぎるブラジル人です。このサイトには、プロジェクト、メモ、実験、そして何かを壊してから学んだことを置いています。

## 一言でいうと

私は **Infrastructure & Platform Engineer** です。ハードウェア、Linux、ネットワークから、ストレージ、コンテナ、サービス、データベース、自動化、その上で動くアプリケーションまで、システム全体を構築し運用することが好きです。データベースは仕事の重要な一部であり、強いソフトウェア開発の背景があるため、アプリケーションとその下のプラットフォームをまたぐ問題も追えます。

## システムとインフラ

私は動いている部品の近くにいるのが好きです。プロセスがどこで動くか、どう起動するか、データがどこにあるか、マシンがどう通信するか、サービスが不調なときにどう復旧するかを知りたいと思っています。

私の仕事と実験には、Linux サーバー、Docker と Compose、永続ストレージ、プライベートネットワーク、クラウドとオンプレミスのワークロード、セルフホストサービス、スクリプト、CI、ログ、監視、トラブルシューティングが含まれます。私にとって自然な流れは、hardware → Linux → network → storage → containers → services → databases → automation → applications です。

## homelab とハードウェア

homelab は一つのデータベースを学ぶためだけの場所ではありません。物理マシンとクラウドノード、x86 と ARM64、プライベートネットワークと公開入口にまたがって、システムを構築し、運用し、壊し、復旧し、文書化する、現実に変化し続ける環境です。

サーバーと homelab のハードウェアは特に好きな分野です。CPU、メモリ、ECC、ストレージ、消費電力、容量を評価し、それぞれのマシンの役割を考え、ワークロードに適切な場所を与えます。そこで動くサービスと同じくらい、マシンそのものとその制約を大切にしています。

## 開発とデータベース

開発は今でも実践的な仕事の一部です。Python、shell、Go、Node.js、TypeScript、SQL、Web ツールを、スクリプト、自動化、API、内部サービス、統合に使っています。この背景は、障害が複数の層にまたがり、答えが単なる「コンテナを再起動」ではないときに役立ちます。

PostgreSQL、pgvector、Redis、バックアップとリストア、データ移行、性能調査、永続サービスは、私の経験の重要な部分です。データベースは深く扱うレイヤーの一つであって、私の肩書き全体ではありません。

## 仕事の進め方

理解でき、観測でき、復旧できるシステムを好みます。実務では、作業に近い文書、有用なログとメトリクス、検証済みのバックアップ、反復作業の小さな自動化、そして口伝に頼らず再現できる環境を意味します。

午前3時に直せるほどシンプルなツールが好きです。長いコマンド一覧を暗記するより、ツールの下にある仕組みを理解する方が大切です。
